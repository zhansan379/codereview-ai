# 主动补拉（轮询轨）

webhook（实时轨）之外的第二条审查触发通道：按间隔轮询或手动触发，把打开态 PR/MR 拉出来入队审查。与平台无关，GitHub、Gitee 通用，接入步骤见 [GitHub 接入教程](how_use_github.md) / [Gitee 接入教程](how_use_gitee.md)。两条通道走同一个队列、同一套回写与统计，可任选也可并用。

## 什么时候用它

- **本地 / 内网部署** —— 平台服务器访问不到你的服务地址，webhook 根本打不进来；
- **webhook 漏事件** —— 服务重启期间的事件、webhook 配置失误导致的漏审；
- **存量 PR 补审** —— 项目刚接入时已经开着一批 PR，开箱先把存量捞回来；
- **服务不出公网** —— 完全不暴露服务地址，靠轮询拿任务。

## 三种触发方式

- **调度页**：配置 poll 类型的定时任务（如每小时一轮）；
- **环境变量**：`.env` 里 `CR_POLL_ENABLED=true`、`CR_POLL_INTERVAL_SECONDS=3600`；
- **手动**：补拉页点「立即补拉」，立即扫一轮所有启用项目。

## 补拉范围与幂等

补拉范围默认只拉**打开态** PR/MR；要连已关闭/已合并一起拉（用于回溯补审），开 `CR_POLL_INCLUDE_CLOSED=true` 或后台「补拉范围」开关。

已审过的同一 head 提交会被增量决策自动跳过，重复补拉天然幂等——所以补拉和 webhook 并用也不会重复审查、重复花钱。
